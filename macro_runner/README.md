# 자동예약 매크로 - 로컬 실행 엔진

`/macro`(https://aft-hcwf.onrender.com/macro) 화면에서 설정한 자동예약
매크로를 **실제로 실행하는** 도구다. 이 폴더는 배포된 AFT 앱(Render)이나
스크래핑 워커(GCP Cloud Run)와 완전히 분리되어 있고, **반드시 예약을
직접 실행할 사람의 PC에서** 실행한다.

## 왜 서버가 아니라 내 PC에서 실행하나요?

- 마지막 "예약하기" 단계는 기본적으로 **사람이 직접 확인 후 클릭**하도록
  되어 있다. 서버에서 보이지 않는 브라우저(headless)로는 사람이 누를
  수 없다 - 이 도구는 실제 브라우저 창을 화면에 띄운다(`headless=False`).
- 실제 예약 사이트에 자동으로 값을 채워 넣는 건 단순 조회보다 봇으로
  의심받기 쉽다. AFT의 스크래핑 기능도 예전에 클라우드(Render) IP가
  한국 중소 호스팅 사이트에 막힌 적이 있다 - 집/개인 회선 IP로 실행하는
  게 더 자연스럽고 안전하다.
- 이름·전화번호 같은 개인정보와 클릭 좌표를 서버 DB에 새로 저장하지
  않기 위해, 설정은 `/macro` 화면에서 JSON 파일로 **내려받아서**
  이 스크립트에 넘기는 방식을 쓴다(서버 API·토큰 인증 불필요).

## 설치

```bash
cd macro_runner
pip install -r requirements.txt
playwright install chromium
```

## 사용법

`/macro` 웹 화면 없이 **`record.py`로 직접 녹화한 파일을 바로
실행**하는 게 더 간단하다 - 아래 "실제 브라우저 조작으로 단계
녹화하기" 참고. 이 절은 `/macro` 화면에서 단계를 편집·저장해 온
기존 방식이다:

1. `/macro`에서 선사·날짜·인원·예약자 정보·실행 시각·단계를 설정한다.
2. "⬇ 내보내기(JSON)" 버튼을 눌러 `aft_macro_config.json`을 내려받는다.
3. 실행한다:
   ```bash
   python run.py --config /path/to/aft_macro_config.json
   ```
4. 지정한 시각까지 스크립트가 대기하다가, 실제 Chromium 창을 띄우고
   설정된 단계를 순서대로 실행한다.
5. `manual: true`로 표시된 단계(기본값: 마지막 "예약하기")에 도달하면
   스크립트가 멈추고 터미널에 안내가 뜬다 - **브라우저 창에서 직접
   확인 후 예약하기 버튼을 눌러야 한다.** 스크립트는 그동안 아무것도
   자동으로 누르지 않는다.

### 한 단계씩 확인하며 실행하기 (`--stepwise`)

```bash
python run.py --config /path/to/aft_macro_config.json --stepwise
```

`--stepwise`를 붙이면 각 단계를 실행하기 **직전에** 무엇을 할
단계인지(순서·라벨·선택자/좌표/Tab 대상·입력될 값) 터미널에 먼저
보여주고 Enter를 눌러야 그 단계가 실행된다. 이미 화면에 떠 있는 실제
브라우저에서 Tab 이동·클릭·입력·팝업 전환이 한 단계씩 눈앞에서
일어나는 걸 확인하면서 진행할 수 있다. 실제 브라우저에서 일어난
동작은 되돌릴 수 없으므로 "이전 단계로" 기능은 없다 - 중간에
그만두려면 Ctrl+C로 중단한다(열려 있던 브라우저 창은 직접 닫는다).

## 실제 브라우저 조작으로 단계 녹화하기 (`record.py`)

단계를 손으로(또는 `/macro` 화면 좌표 기록으로) 만드는 대신, **실제
브라우저에서 직접 조작한 것을 그대로 녹화**할 수 있다:

```bash
python record.py --url https://chf.sunsang24.com/ship/schedule_fleet --out my_recording.json
```

두 개의 실제 브라우저 창이 뜬다:

- **녹화 대상 창**(1280×800) - 여기서 직접 클릭·입력·Tab 이동을 하면
  된다(자동 조작 아님 - 화면을 보면서 사람이 직접 씀).
- **단계 표시 창**(560×800) - 지금까지 기록된 단계가 0.5초마다
  실시간으로 갱신되어 보인다(이 창 자체를 클릭해도 기록되지 않는다).

다 끝났으면 녹화를 시작한 터미널에서 Enter를 누르면 `--out`에 지정한
JSON 파일로 저장된다.

**단계는 "클릭으로 마감되는 하나의 복합 단계"로 묶인다** - 클릭 전에
있었던 스크롤·입력들은 전부 그 클릭이 마감하는 하나의 단계 안에
`inputs[]`로 들어간다. 메인 창에서는 선택자/좌표 둘 다 신뢰할 수
있지만(녹화·재생 둘 다 뷰포트가 1280×800으로 고정), **팝업(새 창)
안에서는 뜨는 위치가 매번 달라 항상 Tab 이동 횟수로 기록**한다(팝업
클릭에 `tab` 모드를 쓰는 것과 같은 이유). 새 창이 열린 클릭은
`opensPopup: true`로 자동 표시되어 재생 시 `context.expect_page()`로
감싸진다.

이렇게 녹화한 JSON은 `/macro` 웹 화면을 거치지 않고 **곧바로**
`run.py`로 실행할 수 있다 - 녹화 중 팝업에 실제로 타이핑한
예약자명·전화번호는 이미 그 값 그대로 단계 안에 들어 있으므로(템플릿
변수가 아니라 진짜 값), 따로 채워 넣을 게 없다:

```bash
python run.py --config my_recording.json --at 17:00:00     # 오늘 17시에 시작
python run.py --config my_recording.json --at "2026-09-23 17:00:00"
python run.py --config my_recording.json --now             # 지금 바로(테스트용)
python run.py --config my_recording.json --stepwise --now  # 한 단계씩 확인하며 즉시 실행
```

`--at`/`--now`를 안 주면, 녹화 원본 JSON에는 실행 시각 정보가 아예
없으므로 **명령을 실행한 바로 그 순간**을 실행 시각으로 삼는다("오늘
17시"처럼 마음대로 가정하지 않는다 - 이미 지난 시각이면 다음날까지
하염없이 기다리게 되어 "아무 반응 없다"고 오해하기 쉽다).

## 안전하게 미리 연습해보기 (실제 사이트 대신 로컬 목업으로)

실제 sunsang24에 진짜 예약을 걸며 테스트할 수는 없으므로,
`fixtures/`에 레드히어로 팝업과 같은 Tab 순서를 재현한 연습용 페이지를
넣어뒀다:

```bash
python run.py --config fixtures/sample_config.json
```

`fixtures/mock_list.html`(바로예약 버튼) → `fixtures/mock_popup.html`
(실제 팝업과 같은 16단계 Tab 순서)이 열리고, 3초 뒤(테스트용 상대
시간) 단계가 실행되는 걸 눈으로 확인할 수 있다. 이 흐름이 정상 동작함을
먼저 확인한 뒤에만 실제 설정으로 넘어가는 걸 권장한다.

## 단계(step) JSON이 어떻게 실행되는지

각 단계는 세 가지 방식(`mode`) 중 하나로 "동작 지점"을 지정한다:

| mode | 의미 | 비고 |
|---|---|---|
| `selector` | Playwright 선택자 문자열(`text=바로예약`, `#agree_all` 등)을 그대로 사용 | 페이지 구조가 안정적인 곳에 적합 |
| `coord` | 화면 좌표(x, y)를 그대로 클릭 | 화면 크기가 기록 당시와 다르면 어긋날 수 있음(보조 수단) |
| `tab` | 현재 포커스에서 Tab을 `tabCount`번 눌러 이동 후 동작 | **팝업 위치와 무관** - 새 창이 어디에 뜨든 항상 같은 필드에 도달 |

`action`은 그 지점에서 무엇을 할지: `none`(이동만) / `click` /
`clickTimes`(N회 클릭, 값에 `{인원}` 같은 변수 사용 가능) / `input`
(값을 입력, `{이름}` `{전화1}` `{전화2}` `{전화3}` `{인원}` `{날짜}`
치환) / `waitFor` / **`popup`**(이 클릭이 새 창을 띄운다는 뜻 -
이후 단계는 그 새 창을 대상으로 실행됨).

## `coord` 모드를 쓸 때 주의할 것

설정 JSON의 `recWidth`/`recHeight`는 `/macro`의 레코딩 캔버스 크기이자
이 스크립트가 여는 브라우저 창 크기다. `run.py`가 항상 이 크기로
`browser.new_context(viewport=...)`를 열기 때문에, `/macro`에서
"레코딩 해상도"를 바꾸지 않고 그대로 내보냈다면 좌표는 정확히
재현된다. **단, `coord` 모드는 팝업(새 창) 안에서는 절대 쓸 수 없다**
- 새 창은 브라우저 보안 정책상 `/macro` 화면에서 들여다볼 수 없어
  애초에 좌표를 기록할 방법이 없다. 팝업 안 필드는 반드시 `tab` 모드를
  쓴다.
